# E4-11 — Add Nutrition Details sheet and grouped nutrient browsing

## Goal

Replace the E4-10 Nutrition Details placeholder with the complete grouped History nutrient browser required by the frozen Epic 4 contract, without adding another range read, navigation authority, historical calculation path, or target authority.

## Outcome

`Show more nutrition` opens a distinct scrollable Nutrition Details surface within the existing History session. It exposes every canonical nutrient in familiar grouped hierarchy, presents the selected-denominator period average and usable-day evidence, adds optional current reference context, preserves group and scroll state through focused-nutrient drill-down/back, and keeps period paging available. Nutrient selection enters only a bounded focused-nutrient shell; E4-12 owns the actual focused chart and exact daily rows.

## Non-goals

- No focused nutrient chart.
- No exact daily-row implementation.
- No focused target/reference line.
- No Daily Log navigation from a nutrient daily row.
- No swipe navigation between nutrients.
- No horizontal category pages.
- No nutrient pinning or dashboard customization.
- No duplicate overview charts within Nutrition Details.
- No new History range read.
- No backend, API, runtime, SQLite, migration, cache, or authority change.
- No shared canonical nutrient catalog/grouping rewrite.
- No AppNavigator route expansion or persistent UI-state storage.

## Background

E4-10 is merged, archived, and closed. It owns the four-card History overview, exact daily mini-chart selection, the `Show more nutrition` transition, and the existing session-owned `overview | nutrition_details` surface boundary.

E4-05 already projects one E4-04 History range into every canonical nutrient, including each nutrient's selected-denominator average, usable-day count, stable unit, daily evidence, and canonical `groupedRows`.

The existing canonical nutrient grouping utility owns Nutrition Facts ordering, Vitamins, Minerals, Fatty Acids, hierarchy relationships, and an `other` bucket. The canonical catalog currently contains Choline as nutrient kind `other`, so preserving every canonical nutrient requires rendering that existing `Other` bucket rather than deleting or reclassifying Choline.

The existing Daily Nutrition presentation proves the application already has a compatible accordion/hierarchy interaction pattern, but E4-11 must not reuse DailyTargetComparison as historical evidence because History period values remain owned by E4-05.

10. Existing canonical catalog/grouping remains authoritative for nutrient identity, labels, hierarchy, and section membership.
