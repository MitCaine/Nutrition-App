# GH-228 — Align session startup and live workflow guidance

## Goal

Make the single startup command part of every ordinary development session without weakening the trusted capsule/RI controller or leaving stale dependency versions in current guidance.

## Outcome

The startup command applies compatible independent updates, reports the authoritative session state even after an update failure, and leaves selected tool paths in the integrated terminal. Current guides identify this path and the canonical risk register instead of stale version copies.

## Non-goals

No toolchain-line migration, package resolution, lockfile update, product behavior, historical-record rewrite, or change to pinned reviewer/RI authority.

## Background

Issue #228 records the gap between the existing one-command updater and older session-start instructions. The risk guide still contains dependency paths retired from the current lock and risk register.

## Authority and precedence

Issue #228 and its exact trusted-owner authorization; current repository scripts, tests and risk register; this capsule; current session and engineering guides. RI is source evidence, never execution or approval authority.

## Dependencies and prerequisites

Authorized base commit, clean synchronized trusted controller, isolated candidate checkout and installed declared toolchain.

## Owned surface

The exact paths listed in `owned_paths`: session scripts and their focused tests, the current top-level/session/development/engineering/script guides, and this lifecycle capsule.

## Allowed changes

Only those exact authorized paths, bounded to startup behavior and guidance.

## Forbidden changes

No package manifests or locks, security risk-register mutations, release versions, product code, CI workflow, controller gates, or historical evidence changes.

## Acceptance criteria

- [ ] AC-1: Sourcing the startup command selects tool paths and invokes the authoritative session report after independent update steps, including when one update fails; any failure remains nonzero.
- [ ] AC-2: Standalone session reporting remains available, and startup reporting uses the selected Python interpreter.

- [ ] AC-4: Current instructions identify the one-command start and capsule/RI boundary, and current risk prose no longer claims retired versions are installed.
