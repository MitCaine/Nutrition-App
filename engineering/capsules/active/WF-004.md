# WF-004 — Make MERGED task-capsule validation squash-safe

## Goal

Repair the repository-owned task-capsule validator so a clean main or CI checkout does not require retention of pre-squash reviewed Git objects after work has been squash merged.

## Outcome

`MERGED` and `RETROSPECTED` capsules preserve the exact historical `Reviewed commit` that was actually reviewed without requiring that pre-squash object to remain in every future local checkout. Durable integration evidence is validated through the recorded merged commit. Repository closeout passes with the existing completed Epic 4 histories unchanged.

## Non-goals

- No application, backend runtime, API, database, migration, mobile, or product behavior changes.
- No change to Epic 4 scope, acceptance criteria, architecture, or runtime authority.
- No rewriting E4-01 through E4-06 `Reviewed commit` values to squash-merge SHAs.
- No broad relaxation of commit validation for pre-merge task states.
- No GitHub API, `gh`, network lookup, or other remote dependency in task-capsule validation.
- No unrelated validator cleanup.

## Background

Repository closeout currently fails because `scripts/validate-task-capsules.py` requires `Reviewed commit` in every `MERGED` or `RETROSPECTED` capsule to resolve through the current local Git object database.

That is not a durable invariant after squash merge. The pre-squash reviewed commit can cease to be reachable or fetched in a later main checkout even though it remains the truthful historical review identity.

The failure currently affects completed E4-01, E4-02, E4-03, E4-03-C1, E4-04, and E4-05. E4-06 passes only because its reviewed Git object remains available in the current checkout. GitHub #131 owns the correction.

## Allowed changes

- Introduce a narrow distinction between historical reviewed provenance and durable merged integration evidence.
- For `MERGED` and `RETROSPECTED`, validate `Reviewed commit` as an exact full Git SHA without requiring the historical pre-squash object to resolve locally.
- Require the existing recorded merged/integration commit field for completed merged states if repository authority confirms that field is the durable integration record.
- Require that merged integration SHA to be exact and locally resolvable as a commit.
- Verify mainline/history reachability only if that can be expressed through an existing repository-neutral Git invariant without a brittle hard-coded branch assumption.
- Preserve strict local commit resolution in states and fields where the local object is genuinely required before integration.
- Add deterministic temporary-repository regression tests reproducing the squash-merge object-retention failure.
- Update the listed workflow/schema documentation only if the current authority is materially ambiguous and a narrow clarification is necessary.
