# GH-150 — Duplicate Recipes as independent editable Recipes

## Goal

Let an owner deliberately duplicate an existing Recipe into a new independent editable Recipe while
preserving immutable publication and Daily Log history.

## Outcome

The backend and the selected local or remote mobile authority expose `recipe.duplicate`. The result
copies the source's current mutable authored definition into new Recipe/ingredient identities,
starts unpublished, uses deterministic collision-aware naming, replays exactly through established
create idempotency, and opens from the existing Recipe details experience.

## Non-goals

- Persistent Recipe lineage, copied publication revisions, copied historical logs, automatic
  publication, Recipe import/generation, graph redesign, or instruction-authoring expansion.
- E2-15 transfer changes, #139 general remote response validation, migrations, schema changes,
  dependency changes, synchronization, fallback, dual-write, or mixed authority.

## Acceptance criteria

- [x] AC-1: Draft duplication returns one new owner-local Recipe with equivalent authored fields,
  ordered ingredients, shared Food/serving references, and new Recipe/ingredient identities.
- [x] AC-2: Published and `needs_republish` sources produce an unpublished duplicate with null
  publication links, `needs_republish=false`, and no copied immutable revision/projection/history.
- [x] AC-3: Source and duplicate edits, deletion, publication, and republishing remain independent;
  historical Daily Logs stay bound to original immutable publication revisions.
- [x] AC-4: Nested Recipe ingredients retain current owner/active/acyclic graph rules and authored
  amount meaning; stale invalid dependencies fail deterministically.
- [x] AC-5: Active owner-local names allocate `Copy`, `Copy 2`, `Copy 3`, and continue a generated
  copy family; inactive names do not block allocation.
- [x] AC-6: Exact `recipe.duplicate` replay creates one result; changed source context conflicts;
  unavailable completed results never recreate; later source edit/deletion does not affect replay.
- [x] AC-7: PostgreSQL owner serialization precedes receipt reservation, stabilizes source/name/graph
  work, avoids deadlock, allocates distinct concurrent names, and rolls back every partial write.
- [x] AC-8: Local SQLite performs equivalent naming/copy/replay/rollback semantics in one
  `withLocalWriteTransaction` operation with no schema bump.
- [x] AC-9: `RecipesRuntime` exposes one duplicate operation under exactly one selected authority;
  remote and local callers produce equivalent visible results without fallback or translation.
- [x] AC-10: Recipe details exposes an accessible independent-copy action, prevents duplicate taps,
  retains one request ID across retry, refreshes caches, and opens the returned duplicate Recipe.
