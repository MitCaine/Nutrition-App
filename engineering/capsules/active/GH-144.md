# GH-144 — Extend validation for current migration and status drift

## Goal

Make stale migration-head and current project/Epic-status claims in designated canonical current
documentation fail repository documentation validation while preserving historical, versioned, and
intentionally pinned operational references as valid point-in-time evidence.

## Outcome

When complete:

- current-document migration-head assertions are explicitly bounded rather than checked through an
  incomplete ad-hoc list;
- every designated current document that claims the application and/or control migration head is
  required to contain the configured current head for that authority;
- designated current product/status documents are required to retain the repository's current
  Version 1.2 / Epic 4 complete / Epic 5 planned-re-scope status contract;
- historical and versioned planning/evidence documents are excluded from current-authority
  validation even when they intentionally contain predecessor heads;
- focused tests prove current-head drift, status drift, and historical exclusion behavior;
- existing reconciled current documentation passes unchanged;
- ordinary documentation validation, repository audit tooling, and canonical repository review
  remain green.

## Non-goals

- Rewriting E4-17 current-guide reconciliation.
- Updating current documentation merely to exercise the validator.
- Rewriting historical, versioned, release, or evidence records to current migration heads.
- Rejecting every occurrence of an older migration identifier.
- Rejecting intentionally pinned upgrade/downgrade/runbook commands that name historical revisions.
- Changing migration files, executable migration authority, production code, runtime behavior,
  schema, persistence, API contracts, mobile behavior, or project status itself.
- Expanding `scripts/project-audit.json` or its operator-document contract system unless the current
  two-file implementation proves insufficient and the capsule is revised before further work.

## Background

GitHub issue GH-144 was created after the project-wide documentation audit found current guides
stale at application migration `0030` / pre-closure Epic 4 status while executable authority had
already advanced. E4-17 subsequently reconciled the current guides, so GH-144 now owns only the
durable mechanical drift detection requested by the issue.
