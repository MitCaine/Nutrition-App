# GH-154 — Remove credential diagnostics and retire stale WF-003 authority

## Goal

Resolve the two bounded pre-2.0 hygiene findings in GitHub issue #154 without
changing USDA credential semantics or silently reviving historical Workflow v3
experimental work.

## Outcome

Ordinary USDA credential reads emit no credential value, configured-state, or
exact-length diagnostic, while credential lookup/storage behavior remains
unchanged. WF-003 is explicitly cancelled and archived as historical workflow
evidence rather than remaining as stale active authority.

## Non-goals

- Do not redesign USDA credential storage or SecureStore ownership.
- Do not change local/remote runtime authority.
- Do not introduce replacement credential diagnostics.
- Do not implement or re-anchor the WF-003 implementation-result renderer.
- Do not delete WF-003 history or historical handoff evidence.
- Do not refactor unrelated application, workflow, dependency, CI, or release
  surfaces.

## Background

The pre-2.0 repository audit found one unnecessary credential metadata log and
one stale active workflow capsule.

`usdaCredentialStore.ts` trims a stored credential and currently logs whether a
credential is configured plus the exact trimmed length. Neither datum is needed
for runtime behavior.

WF-003 was returned from READY to DECOMPOSED on 2026-08-06 and blocked pending
E1-18 / GitHub issue #22. Issue #22 is now complete. Its prior handoff is
explicitly historical and cannot be executed without re-anchoring.

For the 2.0 boundary, no current release requirement justifies introducing the
medium-risk implementation-result renderer experiment. Leaving WF-003 active
would preserve stale workflow authority, while re-anchoring it would create new
non-release-critical tooling scope. The bounded disposition is therefore to
cancel and archive WF-003 while preserving its history.
