# GH-152-P1 — Restore frozen 0017 converter compatibility with serving-reference ORM growth

## Goal

Restore the Phase 5C historical Recipe converter's ability to execute against
its intentionally frozen application schema at migration 0017 after the
current ServingDefinition ORM mapping gained three reference-measurement
columns at migration 0027.

## Outcome

The converter can again load and convert historical Recipe projections at
0017 without querying columns that do not exist at that schema revision.

Current 0027+ serving-reference behavior remains intact.

The existing converter restart, checkpoint, failure, tamper, and qualification
tests reach their intended behavior instead of collapsing into
`subject_database_failure`.

## Non-goals

- Advancing the historical converter beyond migration 0017.
- Changing migration 0027 or any migration history.
- Repairing the separate performance-fixture nutrient-catalog drift.
- Repairing the separate 0019 metadata-comparison drift.
- Changing Recipe conversion semantics.
- Changing historical archive contents.
- Weakening converter verification or failure behavior.
- Broad ORM loading refactors.

## Background

The unrestricted PostgreSQL backend suite exposed a large Phase 5C failure
cluster while GH-142-P2 was being qualified.

A clean detached-worktree reproduction proved the failures pre-exist P2.

The root PostgreSQL exception is SQLSTATE 42703:
`serving_definitions.reference_quantity` does not exist.

A dynamic model/schema compatibility audit at migration 0017 found exactly four
current mapped columns absent from the historical database:

- `ServingDefinition.reference_quantity`
- `ServingDefinition.reference_unit`
- `ServingDefinition.reference_gram_weight`
- `RecipeIngredient.user_id`

`RecipeIngredient.user_id` is already mapped `deferred=True` specifically for
frozen-0017 converter/qualifier compatibility.

The three ServingDefinition reference fields are currently eager.

Migration 0027 introduced those three nullable fields ten application
migrations after the converter target.

## Authority and precedence

1. GitHub issue https://github.com/MitCaine/Nutrition-App/issues/152 defines the repair series.
2. Historical converter contract keeps execution at migration 0017.

   current compatibility precedent.

6. Current serving-reference application behavior must remain unchanged.
