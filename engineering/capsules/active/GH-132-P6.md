# GH-132-P6 — Differentiate persisted Food and Recipe identities in Saved Foods

## Goal

Use the existing GH-132 Foods and Recipes semantic roles where those two
persisted information categories can coexist in the Saved Foods surface.

## Outcome

Persisted rows rendered by `SavedFoodsScreen.tsx` gain a compact textual
identity badge.

The semantic mapping is:

- `food.is_recipe === false` → `Food`
  - foreground: `theme.colors.foodsForeground`
  - background: `theme.colors.foodsBackground`
- `food.is_recipe === true` → `Recipe`
  - foreground: `theme.colors.recipesForeground`
  - background: `theme.colors.recipesBackground`

The identity treatment applies consistently to persisted Food rows in:

- Favorites preview;
- Recent preview;
- All Saved Foods / Saved Foods search results.

USDA reference-search results remain unchanged because they are not yet
persisted Food identities.

The badge text remains a non-color category cue. Color is supplemental.

Food names, source labels, favorite metadata, recent-use metadata, row actions,
search behavior, ordering, and existing accessibility labels remain unchanged.

## Non-goals

- No new theme role or palette value.
- No modification to existing Foods or Recipes token values.
- No whole-row tinting.
- No destination-level screen tinting.
- No navigation color change.
- No Add Food / logging discovery change.
- No Recipe List change.
- No USDA-result recoloring.
- No source-provenance redesign.
- No favorite, recency, selection, nutrition-quality, adherence, success,
  failure, or warning color semantics.
- No Food API, model, persistence, runtime-authority, or backend change.
- No hard-coded production color.
- No unrelated visual cleanup.

## Background

GH-132-P1 established reusable Foods and Recipes foreground/background roles.

GH-132-P2R1 explicitly reserved feature colors for places where simultaneous
information types need differentiation rather than tinting destinations merely
because they belong to a feature.

A remaining-scope audit found no production consumer for:

- `foodsForeground`
- `foodsBackground`
- `recipesForeground`
- `recipesBackground`

`SavedFoodsScreen.tsx` is a bounded surface where ordinary persisted Foods and
recipe-published Foods can coexist in the same repeated row structures.

The canonical `Food` contract exposes `is_recipe: boolean` independently from
source provenance. `source_kind` and `source_label` continue to describe how a
Food originated.

`foodDiscovery.test.ts` directly renders `SavedFoodsScreen` and already owns
its Favorites preview, Recent preview, All Saved Foods, light-theme, dark-theme,
source-label, ordering, and accessibility behavior.

## Decisions and assumptions

- `Food.is_recipe` is the canonical Food-versus-recipe-publication
  discriminator.
- `source_kind` and `source_label` remain provenance semantics and are not
  repurposed as feature identity.
- A textual `Food` / `Recipe` cue keeps color supplemental.
- Both foreground and background P1 roles should be consumed together as one
  bounded semantic identity treatment.
- Favorites preview, Recent preview, and All Saved Foods should use one
  consistent identity rule.
- USDA search results are reference results before persisted Food selection or
  import and therefore remain neutral.
- Exact badge geometry, spacing, and placement relative to the food name remain
  to be grilled before specification.
- No production implementation is authorized in DRAFT.
