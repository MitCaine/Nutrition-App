# GH-160 — Make the canonical task-capsule template schema-valid

## Goal

Repair the workflow entry point so the canonical task-capsule template is structurally
compatible with the schema-v1 validator and future template/schema structural drift is
detected mechanically.

## Outcome

The canonical template retains the terminal-closeout instructions without introducing an
unsupported schema-v1 section, and ordinary repository capsule validation includes a
placeholder-tolerant structural check of the canonical template.

## Non-goals

- Introducing task-capsule schema version 2.
- Adding a new schema-v1 lifecycle section merely to accommodate instructional prose.
- Changing lifecycle states, normal transitions, terminal HISTORY semantics, recovery
  bindings, or execution-preflight policy.
- Weakening active-capsule or terminal-history validation.
- Changing application, release, persistence, migration, dependency, or CI behavior.

## Background

The post-GH-159 repository audit reproduced a structural contradiction in the current
workflow entry point. `engineering/capsules/TEMPLATE.md` contains a level-two
`Terminal closeout rule` section, while schema-v1 `REQUIRED_SECTIONS` does not include
that section and `split_sections()` rejects every unknown level-two section with
`SECTION_UNKNOWN`.

The normal `validate-task-capsules.py --all` path currently validates active capsules and
terminal HISTORY but does not structurally validate the canonical template, allowing this
contradiction to remain green.

## Authority and precedence

1. `engineering/workflow/TASK_CAPSULE.md` defines the current task-capsule contract.
2. `scripts/validate-task-capsules.py` mechanically enforces schema version 1.
3. `engineering/capsules/TEMPLATE.md` is the canonical authoring template and must remain
   compatible with that contract.
4. `apps/backend/tests/test_task_capsule_validator.py` owns focused regression evidence.
5. GitHub issue #160 owns this bounded correction.

## Dependencies and prerequisites

- Exact clean base `7aa86987b2577055ba145aa9d3d255c78dcaf1e5`.
- GitHub issue #160 remains open.
- Schema version 1 remains the intended current contract.
- The terminal-closeout guidance itself remains valid and must be preserved.
- If repairing the problem requires a schema-contract or lifecycle-policy change, stop and
  return to DECOMPOSED rather than expanding implementation scope.

## Owned surface

- Canonical task-capsule authoring template.
- Schema-v1 validator behavior needed to structurally inspect that template.
- Focused task-capsule validator regression tests.
- This active execution capsule.

## Allowed changes

- Reformat the terminal-closeout guidance inside an existing schema-v1 section so it
  remains visible without becoming a new level-two schema section.
- Add a placeholder-tolerant structural template validator that checks front-matter
  structure, schema metadata keys, required level-two sections, section order, and
  required verification subsections.
- Include that structural template check in the ordinary no-explicit-path / `--all`
  validation surface.
- Add focused tests proving the current canonical template passes and unsupported
  structural drift fails.

## Forbidden changes

- Adding `Terminal closeout rule` to `REQUIRED_SECTIONS`.
- Changing schema version, required lifecycle sections, lifecycle states, or transitions.
- Weakening unknown-section, missing-section, ordering, active-capsule, execution, or
  terminal-history checks.
- Changing HISTORY records or historical recovery data.
- Application, API, persistence, schema, migration, dependency, CI, or release changes.
- Unrelated workflow/documentation cleanup.
