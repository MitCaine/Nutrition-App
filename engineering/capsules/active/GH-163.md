# GH-163 — Continuously run current Recipe duplication and History parity PostgreSQL contracts

## Goal

Close the default-branch PostgreSQL coverage gap that currently allows released Recipe-duplication
locking/idempotency behavior and final E4-16 History parity to regress without either focused suite
running in the ordinary `Backend PostgreSQL 16 contracts` job.

## Outcome

The existing PostgreSQL 16 CI tier continuously executes
`test_recipe_duplication_postgres.py` and `test_e4_16_history_parity_postgres.py` together with its
existing bounded product-contract selection, requires real PostgreSQL infrastructure, and verifies
that the two newly selected isolated-schema prefixes leave no residual database state.

## Non-goals

- Do not enable every `postgres_concurrency` suite in ordinary CI.
- Do not alter the ordinary backend baseline selector or its opt-in marker exclusions.
- Do not change Recipe, History, logging, persistence, schema, migration, API, or application behavior.
- Do not modify either selected PostgreSQL test suite merely to make CI pass.
- Do not modify shared PostgreSQL test infrastructure.
- Do not add Phase 5C/5C4 control-plane, MinIO, Docker/provider, or T0 performance qualification to
  the ordinary PostgreSQL CI job.
- Do not treat SQLite or non-PostgreSQL execution as evidence for this task.

## Background

The post-GH-159 audit identified `AUDIT-05`: the default `Backend PostgreSQL 16 contracts` job uses
an explicit bounded test-file list, but it does not include two PostgreSQL-specific suites that now
protect released product behavior.

Discovery at the frozen base confirmed:

- `test_recipe_duplication_postgres.py` contributes three `postgres_concurrency` tests covering
  concurrent collision-aware naming, same-request convergence without deadlock, and transactional
  rollback.
- `test_e4_16_history_parity_postgres.py` contributes one `postgres_concurrency` test covering the
  final shared local/remote History parity fixture against PostgreSQL 16.
- All four tests pass locally on PostgreSQL 16 with `REQUIRE_POSTGRES_TESTS=1`.
- Both suites already use the canonical isolated PostgreSQL session factory and clean up after
  themselves.
- The current CI residual query does not yet include their `test_recipe_duplicate_` and
  `e4_16_history_parity_` schema prefixes.
- The ordinary backend baseline remains intentionally separate and excludes
  `postgres_concurrency`.
