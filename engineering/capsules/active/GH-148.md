# GH-148 — Align 30-day History nutrient charts to selected date

## Goal

Make every parallel 30-day History nutrient chart reveal the existing shared selected date after the
user selects that date in any chart, without introducing live raw-scroll synchronization or any new
History state authority.

## Outcome

`HistoryDailyBarChart` retains independent local scroll state while reacting to the existing
`selectedDate` prop. If the selected 44-point date slot is outside a scrollable chart's viewport,
that chart scrolls to a bounded centered offset. A selected slot already in view causes no
programmatic movement.

## Non-goals

- No live synchronization of raw horizontal swipe offsets.
- No replacement of horizontal scrolling with a static 30-bar layout.
- No History query, evidence, projection, range, session, or selected-date semantic changes.
- No date aggregation, interpolation, omission, or statistic change.
- No backend, runtime, API, SQLite, storage, or authority change.
- No redesign of focused History.
- No change to 7-day fixed/non-scrollable presentation.

## Background

GitHub #148 records a usability finding from E4-16 physical-device qualification. The four overview
charts already share `selectedChartDate`, but every 30-day `HistoryDailyBarChart` owns an independent
horizontal `ScrollView`. Selecting a date after manually scrolling one chart therefore updates the
semantic selection everywhere while leaving the same selected date offscreen in parallel charts.

The existing component already owns:

- the accepted 44-point scrolling slot geometry;
- the 300-point chart viewport model;
- the independent horizontal `ScrollView`;
- the controlled `selectedDate` prop;
- date selection hit targets.

The repair therefore belongs in the reusable chart component rather than History session or query
state.

- Track that chart's own settled horizontal offset locally.

- Center an offscreen selected slot where chart bounds permit.
- Avoid programmatic scrolling when the selected slot is already fully visible.
- React to controlled `selectedDate` changes.
- Add focused E4-10 regression cases.
- Touch E4-12 tests only if directly required to prove reusable focused-chart behavior.

- Clarify the existing range statistic as `Average` and the existing selected date/value as `Selected day`.
## Forbidden changes

- Do not add a second selected-date state.
- Do not persist chart offsets in History session state.
- Do not synchronize raw swipe offsets between charts.
- Do not add requests, cache state, storage, event buses, or synchronization infrastructure.
- Do not modify History query/projection/range/focused semantic models.
- Do not change chart values, reference lines, gaps, unavailable states, or explicit-zero behavior.
- Do not change the 44-point 30-day slot width.
- Do not change backend/runtime/SQLite/API behavior.
- Do not modify completed capsules.
