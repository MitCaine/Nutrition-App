# GH-152-P3 — Restore frozen 0019 metadata-projection compatibility

## Goal

Restore the historical SQLAlchemy metadata-drift comparison at application
migration `0019_resource_membership_integrity` by projecting only explicitly
proven post-0019 schema objects out of current metadata.

The repair must preserve the frozen 0019 target and current production schema.

## Outcome

`test_0019_sqlalchemy_metadata_has_no_domain_drift` compares current
SQLAlchemy metadata against the exact 0019 database boundary without reporting
legitimate schema growth introduced by migrations 0026, 0027, and 0031.

The comparison continues to detect any unlisted table, column, unique
constraint, or other domain drift.

After this final GH-152 family is repaired, unrestricted backend pytest is
rerun from the P3 task tree and must restore the backend baseline before
GH-142-P2 may resume.

## Non-goals

- Advancing the historical metadata target beyond migration 0019.
- Removing or changing current application tables, columns, constraints, or
  indexes.
- Editing any migration.
- Editing production models or schema-authority code.
- Broadly ignoring current SQLAlchemy metadata.
- Skipping or deselecting the failing metadata test.
- Absorbing unrelated backend failures.
- Changing completed GH-152-P1 or GH-152-P2 history.
- Modifying suspended GH-142-P2.

## Background

Umbrella issue #152 originally summarized P3 as five `add_table` differences.

Exact post-P2 diagnostic instrumentation on default branch `8f15d2dd42782ccb3b9fcedecd20ff177eb717cd` supersedes
that abbreviated assertion description. Alembic `compare_metadata()` returns
exactly five heterogeneous differences:

1. `add_table` — `daily_log_day_completions`;
2. `add_constraint` —
   `food_nutrients.uq_food_nutrients_food_nutrient_basis`;
3. `add_column` — `serving_definitions.reference_quantity`;
4. `add_column` — `serving_definitions.reference_unit`;
5. `add_column` — `serving_definitions.reference_gram_weight`.

All five objects are legitimate schema growth after revision 0019.

Migration provenance is exact:

- `daily_log_day_completions` — migration
  `0031_daily_log_complete_state.py`;
- `food_nutrients.uq_food_nutrients_food_nutrient_basis` — migration
  `0026_food_nutrient_integrity.py`;
- all three ServingDefinition reference columns — migration
  `0027_serving_reference_measurement.py`.

The existing historical projection already has explicit table and column
authorities:

- `_POST_0019_METADATA_TABLES` currently contains exactly two Phase 5C
  activation tables;
- `_POST_0019_METADATA_COLUMNS` currently contains exactly two UserProfile
  calendar/time-zone columns;
- no post-0019 unique-constraint authority exists;
- `_include_0019_schema_object()` currently handles only table and column
  projection.

The repair is therefore a typed historical projection correction in the
existing PostgreSQL test, not a production-schema correction.
