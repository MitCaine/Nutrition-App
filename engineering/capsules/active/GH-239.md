# GH-239 — Reject forbidden changes in intermediate candidate commits

## Goal

Prevent a forbidden intermediate commit from entering protected main when its final candidate tree hides that change.

## Outcome

Every commit introduced after the authorized base obeys the same allowed/forbidden path policy, and the final overlay and profile checks remain intact.

## Non-goals

- No change to path-glob semantics; issue #244 owns that separate contract.
- No application behavior, schema, CI workflow or compatibility-mode change.

## Background

`validate_candidate_scope()` currently checks `git diff B..C` only. A forbidden change followed by a restore can disappear from that overlay while remaining in the committed ancestry. The existing controller uses this function before trusted qualification. Revision-one C2 3eb21f194c91d06f62b2310021205a219485e565 was rejected at attachment because planning omitted the mandatory ios-native profile for scripts/lib/task_authorization.py. Revision-two candidate ac5f185004ee94195b9d914c951328b67c71a770 was never attached or qualified. Both attempts remain preserved in local recovery refs; revision three starts from the authenticated base with the corrected profile authority.
