# GH-132-P5 — Differentiate Daily Log compact nutrient categories

## Goal

Apply the existing GH-132 nutrition-series color vocabulary to the compact
four-row Daily Log Nutrition summary so Calories, Protein, Carbohydrate, and
Fat are easier to distinguish at a glance without changing nutrition,
target, or adherence semantics.

## Outcome

Each existing compact nutrient label gains one small circular semantic-series
marker immediately before the textual label.

The mapping is exact:

- Calories → `theme.colors.nutritionCaloriesSeries`
- Protein → `theme.colors.nutritionProteinSeries`
- Carbohydrate → `theme.colors.nutritionCarbohydrateSeries`
- Fat → `theme.colors.nutritionFatSeries`

Each marker is exactly 10 by 10 pixels with a 5-pixel radius.

The existing textual nutrient label remains the semantic carrier. Markers are
supplemental/decorative and add no independent accessibility meaning.

Marker color is based only on nutrient identity. It does not vary with logged
amount, availability, target configuration, remaining/over state, completion,
adherence, success, failure, warning, or nutrition quality.

Labels, values, units, backgrounds, borders, CTAs, completion controls, and
surrounding Daily Log presentation remain neutral.

## Non-goals

- No new theme token or palette change.
- No modification to existing nutrition-series token values.
- No full Daily Nutrition screen change.
- No History change.
- No target-progress or nutrition-calculation change.
- No adherence, success, failure, warning, or quality color semantics.
- No nutrient-label or nutrient-value recoloring.
- No row/card background coloring.
- No Daily Log data, navigation, completion, mutation, recovery, or authority
  change.
- No backend, API, persistence, package, migration, CI, or workflow change
  outside this capsule.
- No hard-coded production color.

## Background

GH-132-P1 established four reusable nutrition-series colors.

The completed History sequence now consumes that vocabulary. The next bounded
consumer is the compact Nutrition section in `DailyLogScreen.tsx`, where
Calories, Protein, Carbohydrate, and Fat currently appear as structurally
equivalent rows.

`dailyLogScreen.test.ts` directly renders and exercises this surface.

`e4_07DailyLogShell.test.ts` owns the four-nutrient projection/value contract
and remains read-only because P5 changes presentation only.

`e4_08DailyNutrition.test.ts` covers the separate full Daily Nutrition screen
and remains outside P5.

The original P5 binding command produced a shell-induced false negative.
Follow-up object diagnosis and recovery proved the exact commit tree, object
database, production path, all relevant blobs, clean worktree, and open issue
