# GH-141 — Remove proven dead Target code and tighten unused-code gates

## Goal

Remove the high-confidence dead Target-era code, tests, shared-contract artifact, and unused mobile
dependencies identified by the project-wide cleanup audit, then make equivalent future drift fail
ordinary TypeScript and pytest validation.

## Outcome

When complete:

- obsolete Target progress UI and its isolated error-translation path are absent;
- the nine superseded per-nutrient recommendation helpers and dedicated tests are absent while the
  canonical versioned DRI resolver remains authoritative;
- the unconsumed legacy shared-contract nutrition-types artifact is absent;
- the two unconsumed mobile dependencies are removed with the lockfile regenerated normally;
- all current strict TypeScript unused diagnostics are resolved;
- ordinary mobile typechecking enforces unused locals and parameters;
- ordinary pytest execution centrally rejects unregistered markers;
- Daily Nutrition, Targets, accessibility, and ordinary repository baselines remain green.

## Non-goals

- Changing Target calculations, DRI semantics, Daily Nutrition behavior, accessibility behavior, or
  navigation behavior.
- Refactoring live Target, Daily Log, History, Recipe, USDA, or accessibility code beyond deletion
  of the six proven unused declarations/imports.
- Removing `Settings.cors_origins`.
- Removing or changing the local-runtime, exact-value, or SQLite barrel entry points.
- Adding or removing schema, migrations, API contracts, persistence, synchronization, fallback, or
  runtime authority.
- Rewriting historical implementation documentation merely because it references code that was
  valid at the time recorded.

## Background

GitHub issue GH-141 records cleanup candidates found by the project-wide audit.

The required current-tree re-audit completed on 2026-08-21 against
`d5974d6cb965fadce732e92c904a18e09db3677f`.

It established:

- `TargetProgressSection.tsx` has no production importer. Remaining references are its dedicated
  test, three obsolete Jest mocks, historical/project documentation, and completed capsule
  evidence.
- `userFacingEpicOneError` is consumed only by the dead Target component and its dedicated tests.
  Independent name search found no separate consumer for the file's exported error types.
- exactly nine `*Recommendation.ts` helpers remain and each is referenced only by its own dedicated
  test. Canonical DRI recommendation coverage remains separately present.
- `packages/shared-contracts/nutrition-types/index.ts` has no path/import consumer or configuration
  consumer. Similar type names elsewhere belong to active, separate contracts.
- `@react-navigation/native` and `react-hook-form` occur only in mobile package manifests/lockfile.
- `noUnusedLocals` and `noUnusedParameters` are absent from mobile TypeScript configuration.
- strict unused checking currently reports exactly six diagnostics: two tests and four production
  files.
- pytest marker names are registered centrally, `--strict-markers` is not yet centrally enabled,
  and the complete 2,250-test collection succeeds with `--strict-markers`.
- the CORS and barrel candidates remain conditional and are not authorized for deletion.
