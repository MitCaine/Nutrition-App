# GH-140 — Run completed Epic 4 PostgreSQL contract suites in CI

## Goal

Make the already-completed Epic 4 PostgreSQL product contracts part of ordinary PostgreSQL 16 CI so regressions in Complete persistence, deterministic Complete mutation, atomic Complete invalidation, and bounded History range behavior cannot pass normal CI unnoticed.

## Outcome

The existing `backend-postgres` CI job continues to run a deliberately bounded product-contract file list, expanded to include the completed E4-01 through E4-04 PostgreSQL suites.

The job continues to require PostgreSQL test prerequisites explicitly and leaves no residual qualification schemas/databases.

## Non-goals

- No new Epic 4 product behavior.
- No E4-16 parity fixture or physical-device qualification.
- No backend production change.
- No test-semantic rewrite.
- No migration change.
- No blanket execution of every `postgres_concurrency` test.
- No Phase 5 historical qualification expansion.
- No MinIO qualification.
- No Docker/provider restart qualification.
- No performance/T0 qualification.
- No GitHub Actions restructuring unrelated to the PostgreSQL job.

## Background

The repository's ordinary PostgreSQL 16 CI job currently selects a bounded list of product-contract tests.

Completed E4-01 through E4-04 introduced additional PostgreSQL contracts covering:

- Complete persistence and migration behavior;
- deterministic and owner-scoped Complete mutation;
- atomic/concurrent Complete invalidation;
- bounded owner-scoped History range semantics.

These completed tests are intentionally marked `postgres_concurrency` because they require a real PostgreSQL server, but the ordinary CI job currently does not name their files.

GitHub #140 records 12 completed tests across these four suites as absent from ordinary PostgreSQL CI.

The correct repair is explicit file selection inside the existing PostgreSQL tier, not changing marker policy globally.

E4-16/#129 remains a separate broad release-qualification task. GH-140 is durable CI follow-through only.

1. GitHub #140 owns this CI correction.
