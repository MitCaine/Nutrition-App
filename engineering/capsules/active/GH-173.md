# GH-173 — Harden iOS build portability and repository state paths

## Goal

Remove repository-path assumptions that broke native iOS generation after the checkout moved to a path containing spaces, and remove machine-specific absolute repository paths from GitHub issue-state artifacts.

## Outcome

The repository generates and qualifies its iOS native project from a checkout path containing spaces without shell path-splitting failures, while GitHub issue-state artifacts store portable repository-relative source paths.

## Non-goals

- Changing application behavior, nutrition-domain logic, database schemas, or backend runtime behavior.
- Reworking generated CocoaPods or Xcode files directly instead of repository-owned generation logic.
- General cleanup of unrelated historical absolute paths that are valid evidence, fixtures, generated environments, container configuration, or URI/security test data.
- Changing the weekly local Personal Team refresh launcher, which is outside repository-controlled state.

## Background

The repository checkout moved from `/Users/mipoo/Nutrition App` to `/Users/mipoo/Projects/Nutrition App`. Regenerating the native iOS project exposed path-splitting defects in repository-controlled Expo/CocoaPods integration, including React Native Info.plist discovery and CocoaPods XCFramework diagnostics. Separate repository-state review found tracked GitHub issue-state artifacts embedding the former absolute checkout path.

The implementation was completed and validated before the repository's required Task Capsule integration gate was encountered. GH-173 formalizes that already-completed work so the exact repository state can pass the canonical qualification and integration workflow.
