# GH-244 — Define component-aware authorized path pattern semantics

## Goal

Remove slash-crossing `fnmatch` ambiguity from newly authorized edit scopes while preserving the exact meaning and evidence binding of retained v1 authority.

## Outcome

New v2 external authorization, capsule attachment, and bounded execution use one documented component-aware path matcher. Retained v1 authorization and its attached/qualified state continue to use the frozen v1 matcher until separately reauthorized. Exact-source and guarded integration checks remain intact.

## Non-goals

- No change to the bytes, marker, digest, parser result or scope semantics of existing authorization-v1 comments and state; no capsule schema change, product code, profile registration, dedicated-App qualification, independent review, or protected integration policy change. The new v2 authorization marker/schema is in scope.
- No broad cleanup of glob consumers outside the three authorized enforcement surfaces; any necessary caller outside owned paths requires `STOP_REPLAN`.

## Background

At B, `task_authorization._path_matches`, `candidate_evidence.attach`, and `capsule_execution.permitted` use Python `fnmatch`, which permits `*` to cross `/`. `_normalize_paths` rejects empty components and trailing slashes, so an explicit subtree pattern can use `root/**` without accepting `root/`. Current bare `apps/backend` is exact, not descendant authority. Retained v1 records can include wildcard forbidden patterns, so changing their interpretation in place could broaden permission even if allowed patterns narrow. R1 candidate `d9a4f5a` remains failed evidence because its owner grant omitted the active capsule path. ## Decisions and assumptions

- Version decision: keep the existing `nutrition-task-authorization:v1` comment marker, `schema_version=1`, canonical payload and digest unchanged; resolve and serialize v1 exactly as before. Introduce a distinct `v2` marker and `schema_version=2` with the same bounded fields, canonical digest including version, and default new payload/comment creation to v2 inside `task_authorization.py`. The authenticated comment version selects the matching policy; never infer it from date, branch, capsule text, candidate source, or observed paths. Reject marker/schema mismatch and unknown versions. Candidate evidence and execution carry that authenticated selection, while v1 saved authorization dictionaries retain their old shape and compare byte-for-byte. If that compatibility cannot be achieved inside owned files, `STOP_REPLAN` rather than altering `scripts/task.py` without authority.
- V1 matching decision: preserve the existing `path == pattern or fnmatch.fnmatchcase(path, pattern)` operation and v1 path validation for every retained allowed and forbidden pattern. V2 matching decision: literal `root` is exact; `root/**` explicitly covers root and its descendants; `*` is exactly one complete component; `**` is zero or more complete components. Only complete `*` and `**` components are wildcards; reject `?`, bracket classes, embedded stars, empty/`.`/`..` components, absolute paths and backslashes. Path identity is a real repository-relative Git path, not string-prefix containment.
- Transition decision: authenticated v1 stays v1 through retained attached, qualified and checkpoint resume paths, including forbidden patterns. New v2 authority uses only v2 across all three enforcement surfaces. To move an existing task to v2, obtain a new trusted-owner comment and authorization identity, replan the capsule and candidate and collect fresh qualification/review; preserve old evidence. The current #244 revision 5 v1 comment is exact-path-only and thus has the same allowed result under either matcher, but is still processed as v1. No automatic state rewrite occurs.
- Evidence decision: the isolated focused command remains required and must pass matching, authorization, candidate evidence, execution scope, source-identity and guarded assertions. Only exact fixtures requiring nested `/usr/bin/sandbox-exec` may skip after a direct capability probe proves nesting unavailable, plus the explicitly opt-in candidate-evidence native capture fixture; the accepted reviewer inspects those skips and does not infer native behavior. The preserved direct C2 macOS run and r3 baseline rehearsal are diagnostic, not C5 acceptance evidence. The isolated `session-end.sh` baseline is required for C5. No unqualified `sandbox_profile` runtime-permission change is part of this task.
