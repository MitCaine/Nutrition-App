# GH-168 — Restore Expo 57 patch compatibility baseline

## Goal

Restore the existing Expo 57 mobile compatibility baseline after upstream Expo compatibility metadata advanced beyond the patch releases currently recorded in the mobile manifest and lockfile.

## Outcome

The mobile dependency manifest and lockfile use the current supported Expo 57 patch versions, the existing mobile qualification is green again, and GH-165-P3 can later revise its base and qualify without weakening its mobile gate.

## Non-goals

- Do not perform an Expo SDK migration.
- Do not perform a React Native migration.
- Do not change product behavior or mobile application source.
- Do not change CI workflows or qualification policy.
- Do not perform unrelated dependency cleanup or a security-remediation sweep.
- Do not modify GH-165-P3 as part of this task.

## Background

GH-165-P3 fresh qualification failed only in Mobile baseline at npm exec -- expo install --check.

The exact failed candidate was 8602eb53e7dc11049925915149f7af4305d599f3. Repository validation, Backend baseline, and Backend PostgreSQL 16 contracts passed on that same candidate.

The mobile package manifest, mobile lockfile, and CI workflow were byte-identical between the GH-165-P3 base and candidate. The failure therefore reflects upstream Expo compatibility metadata drift rather than a GH-165-P3 source regression.

Expo reported these required patch alignments:

- expo: 57.0.15 to ~57.0.16
- expo-crypto: 57.0.1 to ~57.0.2
- expo-image-picker: 57.0.12 to ~57.0.13
- expo-sharing: 57.0.14 to ~57.0.15
