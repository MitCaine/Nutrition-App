# GH-132-P3 — Differentiate History nutrition series and selected dates

## Goal

Use the frozen P1 nutrition-series palette where multiple nutrition categories
actually coexist: the four canonical History overview charts. At the same time,
make chart-date selection supplemental to color by giving selected dates a
restrained non-color marker instead of changing a numeric bar away from its
series identity.

## Outcome

History overview displays the four canonical series using exactly:

- Calories → `nutritionCaloriesSeries`;
- Protein → `nutritionProteinSeries`;
- Carbohydrate → `nutritionCarbohydrateSeries`;
- Fat → `nutritionFatSeries`.

Each overview bar keeps its series color even when its date is selected.

`HistoryDailyBarChart` uses a small circular selection marker for every selected
date:

- numeric selected dates retain `barColor` and receive a marker associated with
  the selected bar/slot;
- gap or unavailable selected dates retain the existing marker concept near the
  baseline;
- marker color is supplied separately from bar-series color and uses the
  existing theme text color at the History call sites.

The shared focused-nutrient History chart remains generic `accent` because an
arbitrary nutrient is not one of the four co-present overview categories. It
does, however, gain the same shape-based selected-date cue.

No nutrition amount, target, denominator, projection, History data, or
accessibility semantics change.

## Non-goals

- No Foods teal, Recipes violet, Daily Log blue, or History indigo as
  whole-screen identity.
- No use of `historyForeground` or `historyBackground` merely because this is a
  History screen.
- No recoloring of Nutrition Details rows or arbitrary focused nutrients by
  nutrient class.
- No red/green or other pass/fail treatment based on target adherence.
- No change to target calculations, target meaning, averages, denominator
  logic, projections, evidence, dates, or persistence.
- No chart dimension, scrolling, slot-width, touch-target, scale, baseline, or
  reference-line change.
- No new theme role and no palette-value change.
- No hard-coded color.
- No navigation or other feature-screen color change.

## Background

GitHub issue #132 identifies repeated blue charts, controls, gray text, gray
borders, and neutral cards as a visually mechanical pattern and asks for
semantic color that remains supplemental rather than judgmental.

GH-132-P1 established four frozen nutrition-series tokens but deliberately left
them unused by feature screens.

GH-132-P2 attempted feature-specific bottom-navigation colors. Physical review
rejected that semantic model because navigation already communicates
destination selection without needing destination-specific hue.

GH-132-P2R1 replaced selected navigation with one universal blue treatment and
established the corrected principle: semantic colors should be consumed where
co-present information categories need differentiation.

Fresh P3 discovery on exact base `43e3640edb4f3ac3c9ffa447bfae227b89e967fd` found that History overview is such a
surface:

- exactly four canonical cards coexist: Calories, Protein, Carbohydrate, Fat;
- all four currently pass generic `theme.colors.accent` to their charts;
- all four P1 `nutrition*Series` tokens have zero production consumers;
- numeric selected bars currently change fill to `selectedBarColor`;
- nonnumeric selected dates already use a small circular marker;
- accessibility selected state already exists;
- no numeric shape marker currently supplements selected-bar color;
- focused History reuses the same chart component for arbitrary nutrients.

## Decisions and assumptions


- P3 applies semantic color because four categories coexist on one surface; it
  does not use color merely to brand the History destination.
- The exact P1 nutrition-series palette remains frozen.
- Overview nutrition color identifies data only. It does not express target
  adherence, quality, success, failure, health, or recommendation.
- Selected state has higher interaction importance but does not erase category
  identity: selected numeric bars retain their normal series color.
- A small circle is the selected-date shape cue because the chart already uses
  that shape for nonnumeric selected dates; P3 generalizes an existing visual
  language rather than introducing a large new selection treatment.
- The marker's theme text color provides contrast, but its shape and placement
  are the non-color selection signal.
- The shared marker behavior applies to both overview and focused History
  charts. Only overview series receive the four semantic nutrition colors.
- `historyForeground` and `historyBackground` remain unused until a later
  concrete surface demonstrates a semantic need for them.
