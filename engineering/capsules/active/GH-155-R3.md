# GH-155-R3 — Complete coherent Version 2.0 release authority

Complete issue #155 with one truthful, qualified Version 2.0 source/GitHub
release authority without repeating the predecessor tasks' over-constrained
execution-package bookkeeping.

## Outcome

guidance, a reachable Version 2.0 release record, and a documentation validator
that agrees with the current Version 2.0 product line.

## Background

GH-155, GH-155-R1, and GH-155-R2 were cancelled without implementation
integration.

R1 discovered that `scripts/validate-docs.py` contained stale Version 1.2
current-status assertions and therefore had to be included in governed scope.

R2 correctly included that validator and reproduced the intended 12-path
implementation. It then discovered that the new mandatory
`docs/project/version-2.0-release.md` must be reachable from the Markdown graph
rooted at `README.md`.

The overall R2 allowed surface already contained both the release record and
the existing documentation paths that could link to it. The actual defect was
the execution bookkeeping: R2 froze those already-authorized paths into
separate 5-path and 1-path packages and required validation between them.

R3 keeps the same overall 12-path implementation surface but removes that
unnecessary restriction.
