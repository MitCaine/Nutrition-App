# GH-153-R1 — Validate remaining supported remote API responses after fixture-scope correction

## Goal

Complete deterministic runtime validation for every supported mobile remote API
response family selected by issue #153, using the already-proven GH-153
implementation design while correcting the baseline-fixture scope defect that
forced GH-153 to terminate.

## Outcome

The 28 response operations that remained outside GH-139 fail closed at their
capability API boundaries when successful remote responses violate canonical
backend contracts.

Together with the 14 previously validated response operations and two
no-response-body delete operations, all 44 supported remote operations have an
explicit response disposition.

Valid canonical responses retain their existing application behavior. The
generic transport remains domain-agnostic. Remote/local authority semantics do
not change.

## Non-goals

- No global validation inside `apiRequest`.
- No backend contract redesign or API-version change.
- No local SQLite runtime change.
- No synchronization, fallback, dual write, shadow write, or cross-authority
  cache.
- No modification to `remoteNutritionRuntime.ts` or `mapRemoteError.ts`.
- No UI or navigation redesign.
- No weakening of strict response parsers to accommodate incomplete tests.
- No unrelated simplification.
- No expansion beyond the single fixture-scope correction identified by the
  cancelled predecessor.

## Background

GH-153 implemented the intended response-validation design across Food, USDA,
OCR confirmation, Calendar, residual Logging, and residual Recipe boundaries.

Before its required full mobile baseline, that implementation had passed:

- Node 24 TypeScript qualification;
- canonical Expo remote/test configuration;
- the complete 44-operation response inventory;
- composed-runtime invalid-response semantics for reads and mutations;
- 189 focused tests.

The required full Jest baseline then exposed incomplete successful-response
fixtures in `savedFoodsContract.test.ts` and
`e2_17RemoteRuntimeIsolation.test.ts`.

`savedFoodsContract.test.ts` was already allowed. The remote-isolation fixture
was not. Because GH-153 had already entered IN_PROGRESS, its qualified scope
could not legally regress to DECOMPOSED. GH-153 therefore terminated as
CANCELLED at exact commit
`f49ff699730e06a03672a3df941aea6ba3f28b06`.

Its 22-path implementation candidate remains frozen without a product commit in
stash `886e5343c77a9234419b95fccb925454f4f0ed39`.

R1 exists solely to qualify the corrected fixture boundary before that candidate
may be recovered.
