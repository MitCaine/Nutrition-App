# UI-135 — Keep USDA Food Details header generic and move food name into body

## Goal

Complete the route-header consistency audit by ensuring USDA Food Details uses stable page identity in fixed chrome while arbitrary USDA food-description data lives in ordinary scrollable content.

## Outcome

USDA Food Details uses the same fixed `USDA food details` route title in loading, error, and ready states. The complete USDA food name/description appears at the beginning of ready-state scrolling content and wraps naturally. Existing metadata, servings, nutrients, diagnostics, Back behavior, and Import Food behavior remain unchanged.

## Non-goals

- No USDA API, import, credential, runtime, mapping, persistence, or authority changes.
- No USDA serving or nutrient semantic changes.
- No nutrient typography redesign.
- No shared route-header primitive changes.
- No arbitrary USDA-name truncation.
- No horizontal title-reveal gesture.
- No Food or Recipe screen changes.
- No E4-14 Food nutrient-discovery work.

## Background

The full route-header audit after UI-133 found only two remaining entity-derived fixed titles.

UI-134 corrected Recipe Details and is merged, archived, and closed.

USDA Food Details remains the final finding. Its loading/error path already uses the stable fixed title `USDA food details`, but its ready state switches the same fixed header to `preview.data.name`. USDA names/descriptions are arbitrary external entity data and can therefore expand fixed route chrome.

The screen already has the correct USDA preview/import authority. UI-135 only changes where the ready-state entity name is rendered.

## Authority and precedence

1. GitHub #135 owns the accepted USDA Food Details interaction.
2. Existing `useUsdaPreview` remains authoritative for preview data.

4. Existing `fdcId` remains the exact import identity.
5. Existing `onImported` success handoff remains authoritative.
6. Existing `RouteScreenHeader` and `RouteHeaderAction` primitives remain unchanged.
