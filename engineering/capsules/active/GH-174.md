# GH-174 — Restore Expo SDK 57 dependency compatibility baseline

## Goal

Restore the mobile dependency set to the versions currently required by the installed Expo SDK 57 release so that the repository Mobile baseline passes its Expo dependency compatibility gate.

## Outcome

`npm exec -- expo install --check` reports no incompatible Expo or React Native package versions, the mobile lockfile is synchronized with the accepted package manifest, and the repository's affected mobile and native qualification profiles pass.

## Non-goals

- Upgrade from Expo SDK 57 to another Expo SDK major version.
- Perform unrelated dependency modernization, vulnerability remediation, or package cleanup.
- Change application behavior, backend behavior, database contracts, migrations, or mobile feature code.
- Incorporate the GH-173 iOS path-portability implementation into this task.

## Background

The GH-173 qualification run exposed a pre-existing repository baseline failure in the Mobile baseline. Expo SDK 57 currently reports that several committed Expo packages and React Native are behind its expected patch versions. GH-173 did not modify `apps/mobile/package.json` or `apps/mobile/package-lock.json`, so the dependency compatibility defect is being corrected independently under GH-174.

The failing compatibility check reported expected updates for Expo, expo-file-system, expo-font, expo-image-picker, expo-secure-store, expo-sharing, expo-sqlite, and React Native.

## Authority and precedence

1. `apps/mobile/package.json` — committed mobile dependency authority.
2. `apps/mobile/package-lock.json` — reproducible npm dependency resolution.
3. `.github/workflows/ci.yml` — repository Mobile baseline qualification contract.
4. `engineering/capsules/README.md` and `engineering/capsules/TEMPLATE.md` — task lifecycle authority.
5. GitHub issue GH-174 — task scope and disposition authority.

## Dependencies and prerequisites

- Repository baseline is exact `origin/main` commit recorded in `base_commit`.
- Node toolchain remains the repository-pinned Node 24 line.
- npm/Expo tooling must determine the SDK 57-compatible patch set; dependency versions are not to be guessed manually where Expo provides authoritative resolution.
- GH-173 is independent and is not a prerequisite for implementing this dependency correction.

## Owned surface

- `apps/mobile/package.json`
- `apps/mobile/package-lock.json`

These files contain the declared and resolved dependency versions necessary to restore Expo SDK 57 compatibility.

## Allowed changes

- `engineering/capsules/active/GH-174.md` for lifecycle state/evidence updates.
- Dependency changes must remain limited to versions required for Expo SDK 57 compatibility unless validation demonstrates an inseparable lockfile resolution change.

## Forbidden changes

- Backend source, tests, requirements, migrations, or runtime contracts.
- Mobile feature behavior or application modules.
- Repository iOS workaround/plugin implementation.
- Expo SDK major-version migration.
- Unrelated dependency upgrades or vulnerability remediation.
- Generated native project changes unless a repository-owned contract proves they are required and the controller explicitly expands scope before implementation.
