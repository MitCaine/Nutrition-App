# GH-136 — Qualify nutrition_qualifier read access to Daily Log Complete state

## Goal

Close the authority-policy gap exposed by E4-15 so the existing
`nutrition_qualifier` identity can read authoritative Daily Log Complete state
from a qualified current PostgreSQL source without gaining write, schema, role,
or generalized future-object authority.

## Outcome

A qualified PostgreSQL 16 current-runtime source at the new application head
grants `nutrition_qualifier` explicit `SELECT` on
`public.daily_log_day_completions`, preserves the existing Phase 5C4 read-only
role topology, and can be used by E4-15's source-authority probe before
transfer-v3 implementation resumes.

## Non-goals

- E4-15 transfer-contract v3, exporter, validator, importer, backup, or restore changes.
- Daily Log Complete persistence, mutation, invalidation, or user-facing behavior changes.
- Synchronization, replication, fallback, merge, or multi-authority behavior.
- Broad Phase 5C4 role-topology redesign.
- Blanket default privileges or future-object grants.
- Unrelated audit cleanup.

## Background

E4-15 qualification built a disposable PostgreSQL 16 current-runtime source
using the already-qualified E4-01 current-source method and reached exact
application revision `0031_daily_log_complete_state`.

`public.daily_log_day_completions` was correctly owned by `nutrition_owner`.
`nutrition_qualifier` retained `default_transaction_read_only=on` and had no
write privileges on the relation, but `has_table_privilege` showed that it also
lacked `SELECT`. The relation ACL contained owner privileges only.

GitHub #136 was created because E4-15 is not authorized to widen Phase 5C4
authority implicitly. E4-15 remains checkpointed and blocked until this
prerequisite is independently implemented, qualified, reviewed, and integrated.
