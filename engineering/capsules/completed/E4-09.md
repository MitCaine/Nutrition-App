# E4-09 — Build History route, range controls, paging, and coverage mode

## Goal

Replace the deferred History destination with the stable History route/session shell required by Epic 4: authoritative 7-day and 30-day ranges ending no later than yesterday, whole-period paging, first-history bounds, Complete-day versus Logged-day coverage mode, and explicit loading/error/empty behavior.

## Outcome

Opening History from Daily Log creates a fresh History navigation session whose newest range ends on authoritative yesterday rather than inheriting the selected Daily Log date as its analysis endpoint. The selected Daily Log date remains return context so Back restores the exact launching date.

History reads one exact E4-04 range through the existing E4-06 query layer and projects it through E4-05. The user can choose 7 Days or 30 Days, page by whole periods, and switch Complete-day/Logged-day denominator interpretation without creating another authority read. No charts, exhaustive detail sheet, focused nutrient view, backend work, runtime changes, or persistence changes are introduced.

## Non-goals

- No four-card History overview or daily mini charts; E4-10 owns those.
- No Nutrition Details sheet/grouped browsing; E4-11 owns those.
- No focused nutrient History, focused chart, or exact daily rows; E4-12 owns those.
- No 90-day, custom, arbitrary, or unbounded ranges.
- No Today-inclusive History.
- No editing Daily Logs or Complete state from History.
- No historical target reconstruction.
- No new backend endpoint, runtime capability, SQLite table, persistent History cache, or storage authority.
- No change to E4-04 range evidence semantics.
- No change to E4-05 exact projection arithmetic.
- No change to E4-06 query identity, invalidation, stale-response, or refresh semantics.
- No required persisted 7/30 preference in initial E4-09. The PRD permits persistence but does not require it.

## Background

E4-04 already supplies one authority-scoped bounded History range read with inclusive LocalDate bounds, one day record per requested date, Complete state, explicit no-Log gaps, exact nutrient evidence, and authority-global `firstLoggedDate`.

E4-05 already supplies one pure shared projection over that evidence. Its `HistoryProjectionMode` is exactly `complete_days | logged_days`, and its coverage includes requested, logged, and Complete day counts. Switching projection mode changes interpretation of the same evidence rather than retrieval identity.

E4-06 already owns React Query identity and lifecycle. Raw History evidence is keyed by selected authority kind, recovery scope, exact start date, and exact end date. Projection mode is intentionally absent from that key. New-range failures cannot show another range; same-range refresh failures may retain only same-range evidence.

E4-07 added the Daily Log History entry seam and three-tab ownership. The current `daily-log-history` route still renders `DeferredDailyLogSurface`; E4-09 replaces that placeholder only.

## Allowed changes

- Add a History range length type containing exactly `7 | 30`.
- Add a History navigation-session shape containing selected range length, selected end date, and denominator-mode preference/equivalent presentation state.
- Define a fresh History session from authoritative Today with end date equal to yesterday and default range length 7.
- Derive the inclusive start date as `endDate - (rangeLength - 1)` calendar days.
- Changing 7/30 range length re-anchors the History session to its most recent supported endpoint ending yesterday, then recomputes the inclusive start date; this preserves an exact whole-period paging lattice.
- Page Previous/Next by exactly 7 or 30 calendar dates according to the selected range length.
- Disable Next once the currently selected end date is yesterday.
- Retain the authority-global `firstLoggedDate | null` in the AppNavigator-owned History navigation session once any loaded range supplies it, so subsequent whole-period paging does not wait for each intermediate range read merely to rediscover the same global bound.
- Use `firstLoggedDate` to determine whether the candidate previous window contains any possible History evidence. Disable Previous when the entire candidate window ends before `firstLoggedDate`.
- When `firstLoggedDate === null`, expose the no-history authority state and disable Previous.
- Permit the earliest reachable window to extend before `firstLoggedDate` when that same window still contains the first logged date.
- Reuse existing date-only calendar helpers rather than elapsed-hour arithmetic.
- Replace `DeferredDailyLogSurface` for `daily-log-history` with a real `HistoryScreen`.
- Treat the launching Daily Log date as return context only. History analysis range initialization must not use that selected Daily Log date as its endpoint.
- Keep History session state in AppNavigator memory so later E4-10/E4-11/E4-12 child routes can consume the same range/mode context without reconstructing it.
- Clear/start a fresh History session when History is newly launched from Daily Log; do not add persistent storage.
- Render 7 Days / 30 Days controls, Previous / Next controls, selected range label, coverage mode control, and bounded loading/error/refresh/empty states.
- If loaded evidence contains zero Complete dates, use Logged-day projection and omit the Complete/Logged selector entirely rather than showing a disabled Complete choice.
- If loaded evidence contains one or more Complete dates and the session has no explicit denominator selection yet, default to Complete-day projection.
- When Complete dates exist, allow switching globally between Complete days and Logged days.
- Switching denominator mode must call only E4-05 projection over the existing loaded evidence. It must not change start/end dates, E4-06 query key, or perform another authoritative range read.
- Preserve the E4-06 distinction between new-range initial failure and same-range refresh failure.
- Back from History restores the exact Daily Log date that launched the History session.
- Add/update only bounded tests needed for History route/navigation compatibility.
