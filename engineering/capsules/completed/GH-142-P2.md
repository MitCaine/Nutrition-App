# GH-142-P2 — Extract reusable Recipe construction and publication test builders

## Goal

Remove the remaining high-fan-out Recipe construction/publication test-module
authorities by moving stable Recipe builders into an explicit
`tests.support.recipes` module while leaving Daily Log behavior for a separate
GH-142-P3 slice.

## Outcome

When P2 is complete:

- `tests/support/recipes.py` is the explicit reusable Recipe-builder authority;
- `_per_100g_food` moves from `test_stage4_recipes.py` to public support
  function `per_100g_food`;
- `_create_recipe`, `_publish`, and `_history` move from
  `test_recipe_revision_publication.py` to public support functions
  `create_recipe`, `publish_recipe`, and `publication_history`;
- `_published` moves from `test_recipe_revision_logging.py` to public support
  function `published_recipe`;
- existing source tests may retain their historical private local names through
  import aliases, avoiding broad call-site churn;
- all cross-test imports of those five moved helpers are eliminated;
- `_post_log` and `_stored_log` intentionally remain in
  `test_recipe_revision_logging.py` for P3;
- the residual cross-test import graph falls from 39 statements to exactly 23;
- behavior and production code remain unchanged.

## Non-goals

- Moving `_post_log` or `_stored_log`.
- Moving `_create_serving_log`.
- Moving the capture/transition-specific `_published_recipe`.
- Moving `_projection_state`.
- Extracting general Daily Log support.
- Extracting USDA support.
- Refactoring Target, OCR, Phase 5, control-plane, or qualification helpers.
- Refactoring Recipe production behavior.
- Changing Recipe publication semantics.
- Changing helper payloads, endpoint expectations, or persistence semantics.

## Background

GH-142-P1 removed the Food-helper seam and reduced the repository's cross-test
import graph from 65 statements to 39.

A fresh post-P1 audit against
`ec6dbc8710e7c7beab0f58338fc1aef9db290ef4` found 39 residual cross-test
statements across 27 consumers and 14 source test modules.

The dominant remaining source is `test_recipe_revision_logging` with 13
statements. All 13 import `_published`; five also import `_post_log` and/or
`_stored_log`.

The next upstream source is `test_recipe_revision_publication` with five
statements importing `_create_recipe`, `_publish`, and/or `_history`.

That source itself depends on `_per_100g_food` from `test_stage4_recipes`,
which has three consumers.

The resulting authority chain is:

`test_stage4_recipes`
→ `test_recipe_revision_publication`
→ `test_recipe_revision_logging`
→ downstream consumers.

A publication-only extraction that omitted `_per_100g_food` would merely move
a test-module dependency into the new support module. A slice that also moved
`_post_log` and `_stored_log` would cross the intended Recipe/Daily-Log domain
boundary.

P2 therefore extracts the five reusable Recipe construction/publication
builders and leaves Daily Log builders for P3.

   domain-specific support modules without production semantic change.

- Revision 6 records execution start from exact READY checkpoint `b2b2264be963ce22f038f09a9f0cee446f758761`. The 39-statement residual graph, 3 / 5 / 13 Recipe source fan-out, and 8 / 5 pure-versus-mixed `_published` classification were re-proven immediately before mutation. Execution remains limited to the five Recipe construction/publication helpers; Daily Log helpers remain deferred to GH-142-P3.
- Revision 5 records the fully qualified P2 planning contract and promotes
  GH-142-P2 to `READY`.

  helpers.
