# GH-145 — Add thin E2-15 transfer CLI boundary tests

## Goal

Close the remaining E2-15 command-line qualification gap with a small boundary-focused test suite
for the stabilized personal-transfer exporter CLI, without changing transfer data behavior or
duplicating the deeper exporter/package contract suites.

## Outcome

When complete:

- the CLI's required-argument boundary is mechanically covered;
- missing database configuration has deterministic argparse failure behavior;
- representative successful invocation wiring is covered without exercising the real exporter;
- exporter failures map to deterministic sanitized CLI output and exit status;
- connection URLs, credentials, and internal exporter diagnostics are proven absent from normal
  success/failure output;
- the CLI's current transfer metadata is asserted through the existing transfer contract rather
  than duplicated independently;
- existing v1/v2/v3 compatibility and current v3 source-schema semantics remain untouched;
- no production code changes are required.

## Non-goals

- Changing `export_personal_transfer.py`.
- Changing argument names, output JSON, exit codes, exporter behavior, or transfer format.
- Adding new CLI functionality.
- Re-testing PostgreSQL exporter internals.
- Re-testing package canonicalization, import behavior, digest semantics, schema qualification,
  source projection, or transfer-version compatibility already covered elsewhere.
- Executing a real PostgreSQL export in these CLI tests.
- Modifying E2-15 v1/v2/v3 compatibility semantics.
- Updating documentation.
- Refactoring unrelated CLI test infrastructure.

## Background

GitHub issue GH-145 was intentionally deferred until E4-15 stabilized the transfer surface. E4-15
is now complete and the read-only 2026-08-21 audit against
`ac1f8fb07c71d3b9e09b2c802eb835943231b9ec` established that the current CLI is stable and thin.

The audited CLI:

- requires `--owner-id`;
- requires `--output`;
- accepts optional `--acknowledge-frozen-writes`;
- requires `NUTRITION_DATABASE_URL`;
- delegates exactly one operation to `export_personal_transfer`;
- maps `TransferExportError` to sanitized JSON containing only `code` and `status`;
- returns exit `1` for exporter failure;
- returns exit `2` for argparse/configuration failures;
- returns exit `0` for success;
- emits success metadata from the authoritative transfer `CONTRACT`;
- currently reports transfer `format_version` 4 and source schema contract
  `e2-15.pg-0033.v3`.

The audit directly proved:

- missing required CLI arguments exit `2`;
- missing `NUTRITION_DATABASE_URL` exits `2`;
- missing configuration creates no output artifact;
- representative success forwards database URL, owner ID, output path, and frozen-write
  acknowledgement correctly;
- representative success creates the expected mocked output artifact;
- representative success emits no database credential/URL;
- representative exporter failure exits `1`;
- representative exporter failure emits only sanitized `{code,status}` JSON;
- an internal exporter exception message containing a secret is not emitted;
- representative exporter failure creates no output artifact;
- 87 existing non-PostgreSQL E2-15 tests pass;
- repository `project-audit.py pre-commit` passes, including 48 focused audit-tooling tests.

No existing test directly covers `scripts.export_personal_transfer`.
