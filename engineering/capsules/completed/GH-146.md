# GH-146 — Integrate Daily Log Complete with PostgreSQL runtime authority

## Goal

Repair the missing PostgreSQL runtime authority for
`public.daily_log_day_completions` and establish a maintainable current
runtime-authority evolution path without rewriting frozen historical Phase 5C
contracts.

## Outcome

At application revision `0033_complete_runtime_authority`, the
revision-scoped current authority contract classifies every ORM relation,
grants the exact Complete relation privileges required by existing runtime and
read-only identities, and keeps Complete writes synchronized with the canonical
Phase 5C close/reopen fence.

## Non-goals

- Changing Daily Log Complete domain, API, service, or repository semantics.
- Changing E4-15 transfer, backup, restore, or validation artifacts.
- Recasting frozen 0019, 0025, or 0026 evidence as current authority.
- SQLite, synchronization, fallback, dual-write, or multi-authority behavior.
- Role-topology redesign, blanket/default grants, or generalized privilege inference.

## Background

Daily Log Complete was added in 0031 and qualifier read authority in 0032, but
the production runtime identity has no authority on the relation. The existing
repository uses SELECT, INSERT, and DELETE. Historical Phase 5C activation and
maintenance routines were rendered from an older write map, so an isolated
GRANT would drift after canonical close/reopen.

The admitted canary GET `/api/v1/logs/daily-summary` calls the Complete read
service, so its existing behavior requires relation-specific canary SELECT.
