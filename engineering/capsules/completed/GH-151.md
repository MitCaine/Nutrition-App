# GH-151 — Keep Phase 5C and 5C4 infrastructure opt-ins out of ordinary backend baseline

## Goal

Make the ordinary backend regression suite deterministic and environment-independent by preventing
external-infrastructure and performance qualification tests from being selected by the normal
backend baseline.

## Outcome

One canonical ordinary-backend test runner excludes the five registered opt-in marker families.
The repository review runner, GitHub Backend baseline, and testing documentation all use that
canonical runner. Pure Phase 5C/5C4 contract and unit coverage remains in the ordinary baseline,
while specialized PostgreSQL, MinIO, Docker, and performance suites remain explicitly runnable.

## Non-goals

- Repair or weaken Phase 5C/5C4 production behavior or qualification assertions.
- Change PostgreSQL, MinIO, Docker, control-plane, migration, or performance semantics.
- Make specialized infrastructure qualification silently skip when explicitly requested.
- Add global pytest defaults that could hide specialized tests from explicit qualification.
- Absorb the broader strict-marker and unused-code work owned by #141.

## Background

A clean-main diagnostic at `3bea407a84e2e81eeb2668b0cffd1b286f3649ae` under Python 3.12.13
established:

- complete backend collection: 2203 tests;
- candidate ordinary collection: 1738 tests;
- infrastructure/performance opt-in delta: 465 tests;
- `postgres_concurrency`: 451 collected tests;
- `phase5c_performance_t0`: 1 collected test;
- `phase5c4_control_postgres`: 115 collected tests;
- `phase5c4_minio`: 10 collected tests;
- `phase5c4_docker_integration`: 5 collected tests;
- pure/non-infrastructure `test_phase5c4_*.py`: 715 passed, 131 deselected;
- complete ordinary backend regression: 1738 passed, 465 deselected.

All relevant opt-in environment variables were unset. The ordinary Phase 5C4 surface is therefore
green. The defect is test selection: bare `pytest` allows specialized suites to become
environment-dependent participants in ordinary regression when local infrastructure happens to be
reachable.

## Decisions and assumptions

- Revision 3 records bounded implementation of the canonical ordinary-backend selector. `scripts/run-backend-baseline.sh` owns the five-marker exclusion; `scripts/run-review.sh`, GitHub Backend baseline, and testing documentation consume that runner. During qualification, the backend review profile exposed an existing interpreter leak in its session-end step: `project-audit.sh` uses bare `python3`, which resolved to host Python 3.14 without pytest. Because `scripts/run-review.sh` is an owned path, the review runner now prepends the backend virtualenv directory only for session-end when that interpreter exists, preserving the session-end wrapper while making the backend review use its qualified Python toolchain. The resumed review profile passed. No production, migration, marker-registration, specialized assertion, or global pytest-default behavior changed.
- The diagnostic establishes a selection defect rather than a Phase 5C4 behavioral regression.
- The ordinary backend baseline must be explicit and environment-independent.
- A dedicated canonical runner is preferred over global pytest `addopts`, because global defaults
  could silently suppress explicitly requested qualification.
- Specialized suites continue to use direct pytest qualification commands outside the ordinary
  runner.
- The issue's default-branch CI requirement is a post-merge closure gate, not a pre-review
  acceptance condition.
