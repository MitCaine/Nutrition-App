# GH-158 — Consolidate completed task capsules into a durable history index

## Goal

Replace individual terminal task-capsule files in the current repository tree with
one detailed, mechanically validated task-history document while preserving full
schema-v1 capsules for active execution only.

The change also permanently alters terminal closeout so future completed work is
recorded in the history document and its active capsule is removed immediately,
rather than accumulating another `completed/` archive.

## Outcome

`engineering/capsules/HISTORY.md` becomes the durable current-tree index for
terminal task outcomes.

All 69 currently completed capsules are represented exactly once in that history,
with enough detailed metadata, completion evidence, lineage, and Git-history
location information for future archaeology. Their individual completed files are
then absent from the current tree.

After this migration, every future terminal task follows the same lifecycle:
normal planning/execution/review/integration gates remain intact; closeout writes
or updates the task's history entry, validates it, and removes the full active
capsule in the same closeout change. No per-task completed capsule is retained.

## Non-goals

- Rewriting, filtering, squashing, garbage-collecting, or otherwise altering Git history.
- Reducing historical `.git` object storage.
- Weakening active task planning, READY qualification, verification, review, or integration.
- Changing application runtime behavior, APIs, persistence, schemas, migrations, dependencies,
  toolchains, release metadata, or GitHub Actions.
- Moving product, architecture, or operational authority into task history.
- Reproducing every Goal, Background, Non-goal, and Escalation paragraph from every historical
  capsule when the exact full capsule remains recoverable from Git.

## Background

The exact preflight at base
`8fead7f4eefd0a494ecab55dc6a13463f4169494` found zero active task capsules and
69 individual completed capsules occupying 1,783,785 bytes of Markdown in the
current tree. Of those terminal records, 56 are `MERGED` and 13 are `CANCELLED`.

The repository currently validates all 69 files individually. Current workflow
authority explicitly moves `MERGED`, `RETROSPECTED`, and `CANCELLED` capsules
into `engineering/capsules/completed/`.

Current dependency inspection found direct completed-path assumptions in the
capsule validator, validator tests, handoff-renderer test fixtures,
`engineering/capsules/README.md`, and `docs/operations/testing.md`.

The full records do not need to remain checked out forever because Git already
preserves them immutably.

## Escalation conditions

- Any existing completed capsule cannot be represented without losing a durable fact required by
  issue #158.
- A migrated full capsule cannot be recovered from the recorded Git locator.
- The migration cannot distinguish a cancelled/retry/correction chain.
- Strict READY execution semantics would need to weaken.
- Active capsule schema version 1 would need an incompatible change rather than a separate history
  record format.
- Another current repository authority depends on a live completed-capsule file in a way not
  captured by the preflight inventory.
- Implementation requires Git-history rewriting or application/runtime changes.
- More than the exact 69 pre-migration completed task IDs are discovered without an explained
  repository-state change.

## Decisions and assumptions

- The new history document may be detailed; reducing current-tree duplication is more important than
  minimizing the history document to a tiny summary.
- Active task capsule schema version 1 remains unchanged. `HISTORY.md` is a separate durable-history
  format, so this task does not require a task-capsule schema-version migration.
- The uniform recovery locator for the initial migration may use exact base commit
  `8fead7f4eefd0a494ecab55dc6a13463f4169494` plus each capsule's exact historical
  completed-capsule path at that commit because the commit contains the complete
  pre-migration population.
- Future history entries use an exact commit/path where the full active capsule still exists before
  closeout removes it.
- Terminal outcome authority moves to `HISTORY.md`; a terminal task does not require a retained
  full capsule in the current tree.
- For successfully integrated work, the active capsule remains through review/integration and is
  removed only after the durable history entry contains the merged/integration evidence.
- A later retrospective may update the same unique history entry from `MERGED` to `RETROSPECTED`;
  it does not recreate the full capsule.
- Cancelled work is written to history with its cancellation reason, partial-work disposition, and
  historical active-capsule locator before the active capsule is removed.
- The `completed/` directory has no permanent role after this migration and should not be recreated
  for future tasks.
- GH-158 itself should be the first live task closed using the new history-plus-active-removal
  procedure.
- No material assumption remains unresolved.
