# GH-155 — Establish coherent Version 2.0 release authority

## Goal

Make repository startup guidance, executable version metadata, current product
documentation, qualification evidence, tag identity, and GitHub release
artifacts tell one truthful Version 2.0 story.

## Outcome


Version 2.0 has one explicit canonical repository release authority at root
`VERSION`, containing exactly `2.0.0`. Mobile package/lock metadata, Expo
marketing version, backend package metadata, FastAPI API metadata, and current
release documentation deliberately mirror that authority.

The current remote-development story is explicit rather than convenient but
false: local-first SQLite remains the normal product-development path; the
schema-0020 PostgreSQL convenience setup is labeled
`LIMITED_PREACTIVATION_OPERATIONS_SANDBOX`; and current remote runtime work
requires an already qualified/provisioned PostgreSQL authority at
`0033_complete_runtime_authority`. The separately authorized
`0021_target_activation_execution` boundary remains operations-only and no
unqualified `alembic upgrade head` workflow is added.

Version 2.0 declares and qualifies Node 24 and Python 3.12, does not invent
native store build identifiers, preserves historical release/planning evidence,
publishes concise Version 2.0 release notes, rechecks known security/dependency
alerts, and publishes one annotated `v2.0.0` tag plus one GitHub Release only
after the exact integrated release commit passes final qualification.

## Non-goals

- Do not rewrite historical migration history.
- Do not weaken or bypass the special migration/activation safety boundary.
- Do not introduce an unqualified `alembic upgrade head` workflow.
- Do not redesign runtime authority or application architecture.
- Do not reopen or broaden GH-153 or GH-154.
- Do not rewrite historical planning or release evidence merely to make old
  material use current terminology.
- Do not change native build identifiers until their Version 2.0 release role
  is explicitly inventoried and decided.
- Do not create `v2.0.0` or a GitHub Release before the exact final release
  commit has completed the required final qualification.
