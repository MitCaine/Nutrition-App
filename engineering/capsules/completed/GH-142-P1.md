# GH-142-P1 — Extract reusable Food test builders

## Goal

Remove the highest-fan-out backend test-to-test dependency by moving the stable
`food_payload` and `create_food` helpers out of `test_stage2_foods.py` and into
an explicit domain-specific Food test-support module.

## Outcome

When P1 is complete:

- `apps/backend/tests/support/` exists as an explicit test-support package;
- `food_payload` and `create_food` live in `tests.support.foods`;
- `test_stage2_foods.py` imports those helpers rather than defining them;
- all 25 audited external consumers import the Food helpers from
  `tests.support.foods`;
- no consumer imports either helper from `tests.test_stage2_foods`;
- helper behavior and payload contents are unchanged;
- pytest collection remains at the audited 2260 tests;
- affected tests and the backend baseline remain green;
- production code remains unchanged.

## Non-goals

- Extracting Recipe-publication helpers.
- Extracting Daily Log helpers.
- Extracting USDA helpers.
- Extracting Target or OCR helpers.
- Cleaning up Epic-specific low-fan-out helpers.
- Refactoring Phase 5/control/PostgreSQL fixture authorities.
- Changing Food API behavior or Food test data.
- Moving these helpers into `conftest.py`.
- Creating a generic catch-all helper or fixture module.
- Refactoring production code.

## Background

GH-142 was opened after a repository audit found substantial coupling between
backend test modules through direct imports from other `test_*.py` files.

The original issue snapshot reported 76 cross-test import statements across 45
backend test files. A fresh non-mutating audit on 2026-08-21 against base
`8b7dbcbce54458814b71f884bee64e5fc312686c` found:

- 145 backend `test_*.py` modules;
- 65 current cross-test import statements;
- 37 consumer files;
- 15 source test modules.

The largest source is `test_stage2_foods`:

- 26 cross-test import statements;
- 25 unique consumer modules;
- 29 imported Food-helper symbols;
- 24 imported `create_food` symbols;
- 5 imported `food_payload` symbols.

GH-142 is therefore intentionally decomposed rather than implemented as one
37-consumer refactor.

The planned sequence is:

1. GH-142-P1 — Food builders.
2. GH-142-P2 — Recipe-publication builders.
3. GH-142-P3 — Daily Log builders.
4. GH-142-P4 — USDA builders and final residual classification.

Phase 5/control/PostgreSQL qualification imports remain separate unless a later
slice proves a helper is generic test infrastructure rather than an
intentional qualification fixture authority.

Low-fan-out Target, OCR, and Epic-specific helpers are not automatically moved
merely to reduce the raw cross-import count.

## Authority and precedence

1. GitHub issue GH-142 defines the maintainability objective and requires
   domain-specific test-support extraction without production semantic change.
2. The 2026-08-21 repository audit defines the current dependency graph and P1
   scope: 26 Food import statements across 25 consumers.
3. `apps/backend/tests/test_stage2_foods.py` at audited blob
   `83e9ea1d3f12c88c5b44d8378cb3625f4b18ffd4` defines the exact helper behavior
   to preserve.
4. Existing tests define behavioral semantics. This task relocates support
   code; it does not reinterpret Food behavior.
5. `engineering/workflow/TASK_CAPSULE.md` and `STATES.md` govern execution and
   lifecycle transitions.

At the audited source:

- `food_payload(name="Greek Yogurt")` constructs the canonical manual Food
  request payload currently shared by tests;
- `create_food(client, name="Greek Yogurt")` POSTs that payload to
  `/api/v1/foods`;
- `create_food` asserts HTTP 201 and returns `response.json()`.

Those semantics are authority for P1.
