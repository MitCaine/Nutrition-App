# GH-150-P1 — Extend E2-15 transfer for recipe.duplicate receipts

## Goal

Advance the current E2-15 one-time personal transfer format from v3 to v4 so a future completed
`recipe.duplicate` create-idempotency receipt can be exported, validated, transferred, and imported
without making owner transfer fail.

## Outcome

V4 classifies `recipe.duplicate` as a copied portable create-like receipt and validates the
independent duplicate result. Historical v1/v2/v3 contracts remain explicit and unchanged, unknown
operations remain fail-closed, and no Recipe product duplication is implemented.

## Non-goals

- Implementing GH-150 Recipe API/service/runtime/UI behavior.
- Persisting Recipe duplication lineage or requiring the original source Recipe.
- Adding or changing PostgreSQL/SQLite schema, migrations, synchronization, fallback, merge,
  dual-write, or another transfer mechanism.
- Translating, reconstructing, omitting, deleting, or relabeling `recipe.duplicate` receipts.
- Changing Food, Daily Log, Phase 5C authority, dependencies, or unrelated documentation.

## Background

GH-150 is preserved blocked at commit `c1377435a1962e03df9882f10a0f71b50de0e909` because current
format v3 rejects legitimate future `recipe.duplicate` receipts as unsupported. This prerequisite
advances transfer authority first; GH-150 product work remains blocked until this task is integrated
and later restarted from post-prerequisite main.

## Authority and precedence

1. Current E2-15 shared contracts, canonical fixtures, backend/mobile validators, exporter/importer,
   and executable tests.
2. Controller-approved GH-150-P1 specification and GitHub issue #150.
3. Frozen v1/v2 artifacts and the exact current v3 artifacts being frozen.
4. `AGENTS.md`, task-capsule workflow, and repository script guidance.
