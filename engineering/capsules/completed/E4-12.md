# E4-12 — Add focused nutrient History and exact daily rows

## Goal

Replace the bounded E4-11 focused-nutrient placeholder with the complete focused History inspection surface required by Epic 4, using the already-loaded History projection and existing History session rather than introducing another read, calculation authority, route authority, or persistent state owner.

## Outcome

Selecting a nutrient in Nutrition Details opens focused History for that exact canonical nutrient. The surface shows its selected-denominator average, usable-day count, optional current target/reference context, true-zero daily chart, exact seven- or thirty-date Daily values list, selected-date callout, and deliberate navigation to an exact Daily Log date. Back, paging, denominator changes, range changes, and Daily Log round trips preserve the appropriate History session context.

## Non-goals

- No new History range endpoint or read.
- No E4-05 projection or exact-value calculation rewrite.
- No historical target reconstruction.
- No target-history persistence.
- No new chart dependency.
- No weekly aggregation or dropped dates.
- No swipe-left/right nutrient switching.
- No editing food/log data directly from History.
- No Complete mutation from History.
- No trend, adherence, good/bad, improving/worsening, or reward judgments.
- No fourth bottom tab.
- No persistent History UI state in SQLite, AsyncStorage, or server state.
- No backend, runtime, API, SQLite, or migration work.
- No Daily Log visual redesign.

## Background

E4-11 is merged, archived, and closed. It established a distinct Nutrition Details surface and a session-owned `focused_nutrient` placeholder while preserving detail accordion state, detail scroll offset, focused nutrient identity, range, denominator, and selected chart date.

E4-05 already projects every canonical nutrient with its selected-denominator average, nutrient-specific usable-day count, stable canonical unit, and one `HistoryProjectedDailyValue` for every date in the requested range.

Those daily values already preserve numeric, unavailable, and gap states; known and estimated contribution; explicit zero; unknown contributors; whether the date contains Logs; and whether the date is Complete. E4-12 must consume these semantics rather than reinterpret them.

E4-10 already provides the reusable `HistoryDailyBarChart` primitive. Native qualification established 44-point horizontal calendar-date slots for 30-day History instead of unreadably compressing or aggregating observations.

The current History route is rendered by AppNavigator with one HistorySession. Normal History Back clears the session and returns to the Daily Log date from which History was opened. E4-12 additionally needs a bounded Daily Log drill-down path that preserves that session as return context.
