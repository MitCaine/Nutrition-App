# GH-132-P6 — Differentiate persisted Food and Recipe identities in Saved Foods

## Goal

Use the existing GH-132 Foods and Recipes semantic roles where those two
persisted information categories can coexist in the Saved Foods surface.

## Outcome

Persisted rows rendered by `SavedFoodsScreen.tsx` gain a compact textual
identity badge.

The semantic mapping is:

- `food.is_recipe === false` → `Food`
  - foreground: `theme.colors.foodsForeground`
  - background: `theme.colors.foodsBackground`
- `food.is_recipe === true` → `Recipe`
  - foreground: `theme.colors.recipesForeground`
  - background: `theme.colors.recipesBackground`

The identity treatment applies consistently to persisted Food rows in:

- Favorites preview;
- Recent preview;
- All Saved Foods / Saved Foods search results.

USDA reference-search results remain unchanged because they are not yet
persisted Food identities.

The badge text remains a non-color category cue. Color is supplemental.

The grilled visual contract is exact:

- the badge appears immediately after the food name within the same
  name/identity line;
- that name/identity line may wrap when horizontal space is insufficient;
- long food names must not be truncated merely to preserve the badge on the
  first line;
- the badge text is exactly `Food` or `Recipe`;
- badge typography is 12-pixel text, 16-pixel line height, weight `700`;
- badge padding is 6 pixels horizontal and 2 pixels vertical;
- badge corner radius is 10 pixels;
- the gap between the food name and badge is 6 pixels;
- the badge has no border, icon, shadow, or independent action affordance;
- existing provenance/favorite/recent metadata remains on its existing line
  beneath the name/identity treatment;
- the existing parent-row accessibility label remains authoritative and no
  color name is introduced into accessibility wording.

Food names, source labels, favorite metadata, recent-use metadata, row actions,
search behavior, ordering, and existing accessibility labels remain unchanged.

## Non-goals

- No new theme role or palette value.
- No modification to existing Foods or Recipes token values.
- No whole-row tinting.
- No destination-level screen tinting.
- No navigation color change.
- No Add Food / logging discovery change.
- No Recipe List change.
- No USDA-result recoloring.
- No source-provenance redesign.
- No favorite, recency, selection, nutrition-quality, adherence, success,
  failure, or warning color semantics.
- No Food API, model, persistence, runtime-authority, or backend change.
- No hard-coded production color.
- No unrelated visual cleanup.

## Background

GH-132-P1 established reusable Foods and Recipes foreground/background roles.

GH-132-P2R1 explicitly reserved feature colors for places where simultaneous
information types need differentiation rather than tinting destinations merely
because they belong to a feature.

A remaining-scope audit found no production consumer for:

- `foodsForeground`
- `foodsBackground`
- `recipesForeground`
- `recipesBackground`

`SavedFoodsScreen.tsx` is a bounded surface where ordinary persisted Foods and
recipe-published Foods can coexist in the same repeated row structures.

The canonical `Food` contract exposes `is_recipe: boolean` independently from
source provenance. `source_kind` and `source_label` continue to describe how a
Food originated.

`foodDiscovery.test.ts` directly renders `SavedFoodsScreen` and already owns
its Favorites preview, Recent preview, All Saved Foods, light-theme, dark-theme,
source-label, ordering, and accessibility behavior.

### Implementation specification

Production implementation is exact and remains within
`SavedFoodsScreen.tsx`.

1. Add a type-only import of `Food` from `../api/types`.
2. Add one local renderer inside `SavedFoodsScreen` named
   `renderPersistedFoodName(food: Food)`.
3. That renderer returns exactly one wrapping `View` containing:
   - the existing food-name `Text`; and
   - one non-interactive identity-badge `Text`.
4. The badge label is selected only by:
   `food.is_recipe ? "Recipe" : "Food"`.
5. Badge colors are selected by the same boolean only:
   - recipe:
     `recipesForeground` + `recipesBackground`;
   - non-recipe:
     `foodsForeground` + `foodsBackground`.
6. No `source_kind`, `source_label`, brand, favorite, recent-use, nutrient,
   selection, status, or other field participates in identity selection.
7. Use that renderer in exactly these existing persisted-food locations:
   - Favorites preview: `food`;
   - Recent preview: `item.food`;
   - All Saved Foods / Saved Foods results: `food`.
8. Do not invoke the renderer from the USDA-result mapping.
9. Add these styles only:
   - `foodIdentityRow`:
     `alignItems: "center"`,
     `flexDirection: "row"`,
     `flexWrap: "wrap"`,
     `gap: 6`;
   - `foodIdentityName`:
     `flexShrink: 1`;
   - `foodIdentityBadge`:
     `borderRadius: 10`,
     `fontSize: 12`,
     `fontWeight: "700"`,
     `lineHeight: 16`,
     `paddingHorizontal: 6`,
     `paddingVertical: 2`.
10. Render the existing food name with
    `[styles.foodName, styles.foodIdentityName]`.
11. Apply foreground/background badge colors through the existing theme roles
    in the rendered style array; do not create style variants containing new
    color literals.
12. Do not add `numberOfLines`, ellipsizing, icons, borders, shadows,
    accessibility roles, accessibility labels, accessibility hints, press
    handlers, or production `testID`s to the badge.
13. Existing parent `Pressable` accessibility labels remain byte-for-byte
    behaviorally equivalent and remain the accessible row authority.

Direct regression implementation is exact and remains within
`foodDiscovery.test.ts`.

1. Import `StyleSheet` for deterministic flattened-style assertions.
2. Import existing `LIGHT_THEME` and `DARK_THEME` constants; do not duplicate
   palette literals in the test.
3. Add at least one recipe-published `Food` fixture with
   `is_recipe: true`, `source_kind: "recipe"`, and
   `source_label: "Recipe"`.
4. Ensure the rendered fixtures exercise both recipe and non-recipe persisted
   identities in Favorites preview, Recent preview, and All Saved Foods.
5. Preserve at least two distinct non-recipe provenance kinds in coverage so
   the test demonstrates that non-recipe provenance does not alter the `Food`
   identity.
6. Locate badges through descendants of their existing parent rows and textual
   `Food` / `Recipe` content; do not require production `testID`s.
7. Flatten badge styles and assert the exact theme role values plus frozen
   typography, padding, and radius.
8. Run the mapping assertions once with the light theme and once with the dark
   theme.
9. Assert existing parent accessibility labels retain their pre-P6 wording and
   contain no color name.
10. Make USDA search data non-empty in focused coverage and prove the USDA row
    has no `Food` / `Recipe` identity-badge descendant.
11. Preserve all existing Saved Foods discovery, ordering, source-label,
    dynamic-type, Android, retry, and recent-formatting expectations.
