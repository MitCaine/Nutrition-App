# GH-132-P2 — Apply semantic feature identity to bottom navigation

## Goal

Make the P1 semantic feature palette visible for the first time by giving the
three main bottom-navigation destinations restrained, consistent feature
identity while preserving the existing navigation geometry, interaction,
accessibility, and universal action-color language.

## Outcome

The selected bottom-navigation third uses the existing P1 feature identity for
the active tab:

- Foods: `foodsBackground` with `foodsForeground`;
- Daily Log: `dailyLogBackground` with `dailyLogForeground`;
- Recipes: `recipesBackground` with `recipesForeground`.

The selected feature background fills the already-clipped selected third. The
matching feature foreground colors its selected icon, selected label, selected
edge, and selected dividers.

Inactive tabs remain unchanged.

Selection continues to be communicated by the existing non-color cues:

- outlined icon becomes its filled active icon;
- selected label remains bold;
- selected-third clipped geometry and edge remain present;
- `accessibilityState.selected` remains authoritative for accessibility.

P2 changes no theme values and introduces no new hard-coded colors.

## Non-goals

- No change to any P1 palette value or semantic role.
- No feature-colored primary buttons, FABs, form actions, or other action
  controls.
- No Foods, Daily Log, or Recipes screen-surface recoloring; that is P3.
- No History recoloring, nutrition-series application, or chart-selection
  redesign; that is P4.
- No new shared feature-identity abstraction solely for one consumer.
- No new route, tab, navigation state, or swipe behavior.
- No selected-third geometry, dock contour, safe-area, touch-target, or dynamic
  type redesign.
- No inactive-navigation recoloring.
- No backend, API, persistence, runtime, calculation, package, or CI change.
- No red/green nutrition adherence semantics.
