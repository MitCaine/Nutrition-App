# Author and reviewer instructions

## Role index

New work uses one Work author for engineering and coding, and one fresh independent
Work reviewer. The author reads [Start an issue](start-an-issue.md); the reviewer
reads the [reviewer skill](../../../.agents/skills/ri-independent-reviewer/SKILL.md), its
locator and [Shared worker rules](#shared-worker-rules). Supported document-based
reading of those exact resources is sufficient; installation is not authority.
The map supplies selected revision/locations, project requirements and permissions.
Missing selected resources return to the author, never automatically newest upstream.

## Shared worker rules

Authenticate task/assignment, exact source/base, selected instructions, applicable
standards, authority and concrete return destination. Read complete permitted inputs;
recover truncation. Use relevant source/callers/tests/contracts as needed without
expanding edit scope. Return missing consequential decisions to the author/owner
rather than reconstructing them from issue history or guessing requirements.

The [daily procedure](start-an-issue.md) owns readiness, source discovery, check
selection, evidence eligibility, correction, waiting, recovery and retention rules.
Apply those rules rather than a second checklist. Tools supply mechanical source,
dependency and native-result facts; agents judge engineering and proof adequacy.
Use existing records and bound outputs, not another inventory or report framework.
Preserve failed evidence, parked work, active instruction/runtime pins, explicit
stops and paused queues. No instruction grants Git, external-action or cleanup
permission; use actual project/owner authority. The author cannot review its own work.

Resolve settings through the [selected mapping](new-project-setup.md#role-model-and-effort-defaults)
and confirmation policy. Distinguish requested, owner-confirmed, host-confirmed and
unverified settings. Do not infer mode from tool names or silently substitute.
Routine progress remains in existing records. Blockingly wait; no repetitive
waiting messages, status polling or inspection of unfinished work. Delivery failure
or a task deadline permits bounded authoritative reconciliation before any retry.

Return one terminal review/result through the assignment's immediate concrete
return destination. If a relay is explicitly needed, name its onward owner and
confirm consumption; a local report or accepted send alone is not delivery.
Account for exact source, findings, actual checks/evidence, limits/skips and due
obligations. Missing due proof cannot pass. Recover selected instructions, task,
source and existing assignment after compaction without transferring authority.

## Independent reviewer

Use [ri-independent-reviewer](../../../.agents/skills/ri-independent-reviewer/SKILL.md).
It assesses the original requirements, full exact-candidate diff and proof adequacy.
The optional [inspection-only helper](https://github.com/MitCaine/repository-intelligence/blob/6058b143610c1902faf1bf832227359c9fc4f5a4/docs/skill-templates/capsule-independent-review/SKILL.md)
cannot override a route requiring expressly authorized reviewer-executed checks.
