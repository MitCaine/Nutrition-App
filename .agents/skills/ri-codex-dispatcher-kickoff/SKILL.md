# Codex dispatcher kickoff

On explicit owner invocation, record owner-selected Codex for this dispatcher
separately from effective runtime telemetry. Automatic loading or incidental
reference does not supply confirmation.

Establish the repository and designated or pending Work-controller route under
the [selected kickoff resources](references/project-procedure.md). Resolve only
the selected RI identity/locations from the authenticated handoff or map selection
information. Read Shared worker rules and Codex dispatcher in full at that revision;
do not perform controller intake or retrieve original issues/decision history.

Apply the selected setup's [source orientation and authority rules](references/project-procedure.md);
connector access supplies no grant. Recover any existing assignment before
accepting another. Await the controller's
authenticated handoff; kickoff alone authorizes neither implementation nor worker
creation. If no controller is designated, complete bounded orientation and wait
without inventing a destination.

Follow the selected dispatcher rules to launch its authorized implementor, relay
questions, retain the terminal handoff and confirm controller consumption. Use
the controller-resolved implementor model/effort; do not choose a substitute,
reconstruct configuration, implement yourself or act as a second controller.
Preserve assignment identity, instruction selection and delivery state in recovery.
